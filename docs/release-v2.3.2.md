# v2.3.2 稳定性与恢复安全更新

日期：2026-09-05。基线：v2.3.1（508c1575）。本版仅针对桌面测试客户端，不生成 Android APK。

## 已实施

1. 桌面密钥写入失败明确报错，不静默落入本地混淆存储；保存成功和删除时清理旧副本，避免旧密钥复现。
2. 设置页显示实际存储状态，读写期间禁用冲突操作；系统密钥写入成功后再保存 Provider 元数据，失败保留原配置；切换提供商恢复其自定义地址。
3. 旧版 API 配置迁移等待密钥转存成功后才移除 apiKey，失败不提前删除迁移源。
4. 备份先校验文件、预览新增/更新/保留/覆盖范围，再由用户确认。业务数组同 ID 采用较新 updatedAt；同时间或无有效时间保留本机记录。
5. 配置、草稿和会话记忆仍整体覆盖，界面明确提示；旧模型配置数组没有 id，不再被数组去重错误跳过。
6. 模型配置中的 apiKey / api_key / accessToken / secret 等已知字段在导出和导入时剥离。业务原文不修改，备份仍可能包含客户材料或用户写入文档中的秘密，必须妥善保管。
7. 删除实际未调用的 Shell spawn、stdin-write、kill 权限声明。

## 兼容决策与限制

- 保留 com.techdemand.app，避免无升级迁移方案的应用身份变化；构建标识警告暂留，不是已解决项。
- 备份 schema 继续为 1；项目数据结构未变，本版复用现有字段验证，不增加空迁移版本。
- Shell execute 权限与原有命令范围保持不变。本版没有扩大 npx/Node/Claude 的执行授权；终端原生 CLI 白名单及功能联通未验收。
- 旧本地密钥允许兼容读取，并明确提示；在桌面成功重新保存后清理。浏览器开发模式仍为本地混淆，不等同系统加密。
- 备份写入不是跨键事务；空间不足时停止并报告部分恢复，恢复前建议先导出本机备份。
- 备份校验涵盖封装、业务列表 ID 和项目字段，不是全部业务字段的完整 schema 校验。
- 科学技能约 2.27 MB 的资源块优化、UI 2.0 与项目活动时间线保留后续版本。

## 验证

- 前端：24 个测试文件、102 项测试通过（原 78 项，新增 24 项）。
- 覆盖：密钥写入失败、旧副本清理和删除、浏览器兼容模式、异步迁移、备份新旧/同时间冲突、无效包、空间不足、配置密钥剥离、预览确认/取消、设置页保存失败与成功反馈。
- 系统凭据调用通过 mock 验证前端行为；未使用用户真实 API Key 测试模型连通，也不据此宣称系统密钥库实机端到端已通过。
- Rust：cargo test --locked 退出码 0；当前 Rust 单元测试数量为 0，仅作为编译与测试入口检查。
- 构建：npm run tauri build -- --bundles nsis 成功，使用 stable-x86_64-pc-windows-msvc；TypeScript 与 Vite 构建通过。
- 页面：本地 1421 测试实例验证空密钥错误提示、文件选择后的导入预览和取消，检查了预览区截图；浏览器控制台无 error 记录。未对安装后的原生窗口做完整 UI 回归。
- 启动：归档便携 EXE 在无相邻 WebView2Loader.dll 的目录运行 4 秒，核对进程可执行路径后结束本次测试进程；此结果只证明进程启动，不代表全部功能联通。
- 隐私检查：dist 与便携 EXE 的常见 OpenAI/AWS/GitHub 密钥模式（带词边界）为 0 命中；无词边界的扫描曾命中科学技能中 task-rest 文件名，已确认为误报。本检查不是全面秘密审计。
- 已知构建警告：应用标识以 .app 结尾、Rust bin/lib 的 PDB 输出重名、科学技能资源块大于 500 kB。均未在本补丁中扩大改造。
